# Internationalization

Follow these rules when [AGENTS.md](../../AGENTS.md) directs you here. Read
[the implementation guide](../features/i18n.md) before changing language behavior.

## Required translations

- Store every application text in the Fluent catalogs under `locales/`.
- Maintain English (`en`), Russian (`ru`), and Spanish (`es`) for every message.
- Add or update all three translations in the same change.
- Include window titles, labels, buttons, menus, tooltips, placeholders, notifications,
  accessibility descriptions, and errors.
- Localize application-authored console messages and error explanations too.
- Do not embed display text in Rust views, application state, or infrastructure code.
- Keep identical message identifiers across catalogs.
- Register each message in the typed `Key` list in `src/i18n/mod.rs`.
- Use stable identifiers that describe purpose rather than English wording.
- Store complete messages. Do not build translated sentences by joining fragments.
- Use Fluent arguments for dynamic values. Preserve argument names across translations.
- Use Fluent selection rules for quantities when messages require plural forms.
- Preserve product names and technical identifiers where translation would change their meaning.
- Keep user content unchanged. Keep raw external error details only in developer diagnostics.
- Translate diagnostic explanations, but never display diagnostic messages in the product interface.
- Follow [user-facing content rules](user-facing-content.md) for interface wording and error handling.

Source identifiers, protocol values, paths, environment variable names, and test assertions are not
application prose. Documentation and code comments follow
[the documentation language rules](documentation.md). Those rules do not require three documentation
translations.

## Verification

- Test every catalog directly. English fallback must not hide missing translations in tests.
- Check matching identifiers, nonempty messages, valid Fluent syntax, and working arguments.
- Update argument test cases when adding parameterized messages.
- Test visible text and layout in all three languages when changing an interface.
- Test language selection and fallback behavior when changing locale handling.
- Run `make check` and `make build` before completion.
- Treat fallback as runtime recovery. Do not use it to justify incomplete translations.
